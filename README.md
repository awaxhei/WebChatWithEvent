# 尤夏 — 和三无傲娇猫娘青梅同居了！

基于 **事件驱动 + AI 小镇式记忆 + 确定性故事时钟 + 场景化环境** 的三 AI 角色扮演聊天应用。你作为"青梅竹马"与猫娘**尤夏**同居；世界有自己的时间、地点、环境与偶发事件，尤夏也会自己行动。

> **v4** 重构：尤夏只负责说话（对白/消息/表情包）、手机独立通道、环境描写绑定场景、随机事件分级抽取、尤夏自主行动

---

## 功能特性

| 功能 | 说明 |
|------|------|
| **三 AI 架构** | AI A（尤夏对话）→ AI C（世界引擎）；环境改由场景系统按需生成 |
| **自然输出** | 尤夏只输出「对白 / 消息 / 表情包」，短句为主，不写动作和环境 |
| **手机通道** | 手机消息不进主聊天页；左下角手机图标 + 红点，点开才看 |
| **场景化环境** | 环境描写绑定「地点 + 时段」，首次进入生成并缓存，之后零成本复用 |
| **真实地点** | 地点是数据库实体；玩家点地点名即可移动，尤夏也会自己走开 |
| **异地只能手机** | 两人不在同一地点时，交流自动切到手机通道 |
| **随机事件分级** | 程序按权重抽取强度（60/25/12/3），影响越深越稀有，再由 LLM 具体化 |
| **尤夏自主行动** | 不等输入也会主动说话、发消息、换场景；闲置一段时间会主动找你 |
| **场景观察者** | 每轮读对话上下文，发现地点表之外的新场所就自动创建并移动 |
| **神态描写** | 动作/神态由独立一层按上下文生成，不占她的对白格式 |
| **颜文字** | 平时也会带日式颜文字（约每两三条一次），情绪波动时更明显 |
| **AI 小镇式记忆** | 观察/反思两层，检索得分 = 时效×0.5 + 重要度×0.3 + 相关性×0.2 |
| **确定性故事时钟** | 服务器持有唯一时间真值，每轮 +3 分钟，LLM 只能申请"跳跃类型" |
| **自然上下文** | 上层 LLM 把结构化状态写成一段叙述再喂给尤夏，不用方括号标签 |
| **账号系统** | SHA-256 + HttpOnly Cookie，多用户隔离 + 会话归属校验 |
| **自助 API Key** | 页面右上角齿轮可填自己的 Key，只存本机 localStorage |
| **PWA 支持** | manifest + Service Worker + 自动生成图标 |

### 登录时提示"连不上本地服务器"

说明 `5000` 端口上已经没有进程在监听 —— 常见于终端被关掉、或 `python app.py` 启动失败。
页面能打开但不代表服务在跑：Service Worker 会缓存静态资源，旧版本还会把缓存里的首页
当正常页面返回，让人误以为一切正常。

现在的行为是：

- 页面导航连不上后端时，直接显示"服务器未启动"页，并每 3 秒自动重试；
- 登录页会探测 `/api/ping`，失败时给出明确提示和"立即重试"，每 5 秒自动重连；
- 重启 `python app.py` 后，页面自己恢复，不用手动刷新。

排查步骤：看终端有没有退出/报错 → 重新 `python app.py` → 浏览器 `http://127.0.0.1:5000/api/ping`
应返回 `{"ok": true, ...}`。若端口被占，用 `PORT=5001 python app.py` 换端口。

两种填 Key 的方式：`config.py` 里写死，或页面右上角齿轮填自己的（只存本机，通过 `X-DeepSeek-API-Key` 头透传，不落库）。

## 交互模型

### 输出格式

尤夏每次回复是一个或多个 JSON 对象，字段只有三个：

| 字段 | 去处 |
|------|------|
| `对白` | 主聊天页的对话气泡（仅当两人同处一地） |
| `消息` | 手机面板（不进主页，亮红点提醒） |
| `表情包` | 主聊天页的表情图片 |

动作、神态、环境一律不由尤夏输出——环境交给场景系统，动作由玩家自行想象。

**两条通道的语气是分开的**（这是她最核心的反差）：

| 通道 | 语气 |
|------|------|
| 当面 `对白` | 短、平、少，常用省略号；颜文字两三条一次 |
| 手机 `消息` | 活泼、傲娇、带语气词（啦/哦/呀/嘛）和颜文字，常连发两三条 |

**冷淡 ≠ 敷衍。** 三无是"没表情、话少"，不是"没内容"，所以她被额外约束了几条：

| 规则 | 反例（改前常见） |
|---|---|
| 不许用万能词打发（嗯 / 哦 / 随便 / 都行） | 问吃什么只回「随便。」 |
| 每句都要有落点：具体判断、条件或选择范围 | 「面包就行，别加那种甜的酱。」 |
| 别把每个回答都变成反问，连着追问就是在审问 | 三句里两句都是「说清楚点」 |
| 省略号是停顿，不是省略内容 | 「……」单独成句 |
| 允许冷幽默：平语气 + 带刺或意外的内容 | 「冰箱还有两罐咖啡，自己拿。」 |
| 别连续两次用同一个开头 | |

### 动态 NPC（煎饼摊老板这类）

除了尤夏，还可以有只应付简单问答的路人。**按需生成、按需退场，名字不限于固定词表**：

| 触发 | 说明 |
|---|---|
| 句首称呼 | `称呼 + 标点` 的写法都算："老板，来个煎饼""算命先生，给我看看""城管，这摊子能摆吗" |
| @名字 | `@送外卖的 我的单到哪了`，直接指定称呼 |
| 模型判别 | 上面两条都不中时，用一个小模型判断"这句是不是在跟第三人说话"：<br>`给我来个煎饼，多加辣` → 生成摊主 · `你好，这个怎么卖` → 生成店员 · `我觉得老板说得对` → 不生成（只是提到） · `尤夏，你早上吃的什么` → 不生成 |
| 跟进对话 | 上一轮是 NPC 说的，你下一句不用再叫名字也会继续由他接；叫「尤夏」或换称呼则换人 |
| 手动创建 | `POST /api/npcs/<conv>`，字段 `name` / `role` / `location` / `persona` |
| 退场 | `POST /api/npcs/<conv>/<id>/dismiss`，状态变 `gone` |

模型判别（`NPC_DETECT_PROMPT`）**关掉思考、限 120 token**，单次 0.7–1.1 秒；
判不出来称呼时按地点补一个（摊→摊主、店→店员、站→工作人员）。
嫌慢可以关掉 `NPC_LLM_DETECT = False`，退回纯规则识别。

**为什么表不会"只有那几个"**：`npcs` 表是一份**运行时名册**，不是角色定义清单。
名字来自玩家自己的称呼（`算命先生`、`城管`、`收废品的老王` 都可以），身份由后缀推断
（`煎饼摊老板→老板`、`算命先生→算命先生`），人设是模板生成的。

**为什么表不会无限膨胀**：名册有上限，挤满时**请最久没说话的那位退场**：

| 上限 | 值 |
|---|---|
| 单会话同时在场 | `NPC_CAP = 12` |
| 单个地点同时在场 | `PER_LOCATION_CAP = 3`（超出时挤掉该地点最久没说话的） |

NPC 只做一件事：回一两句话（`NPC_PROMPT`，走 flash，30 字上限），不维护长期人设、不推进剧情。

```
你：算命先生，给我看看今天运气
  [算命先生] 把手伸过来，我瞧瞧。今天运气不赖，别自己找事。
  尤夏：「他要是说你今天有大喜，你就信了？」

你：城管，这摊子能摆吗
  [城管] 这儿不让摆，赶紧收了。别处我不管。
  尤夏：「收得比尤夏起床还快，没劲。」
```

实现要点：

- NPC 绑定地点（`npcs.location`），换地方就不在场
- 他说的话存进 `messages.channel = 'npc'`（JSON：`{name, text}`），
  因而同时进尤夏的上下文和世界块的「【现场还有】老板」，她可以接话但不会替他说话
- 前端渲染成带名字的虚线气泡，和尤夏的气泡区分开

> 小边界：如果两人不在一起、你却在别处跟 NPC 说话，那句话仍会作为手机消息发给尤夏，
> 她可能以为你在叫她。同处一地时没有这个问题。

### 两条通道共用一个上下文

她看到的历史是**当面 + 手机合并成的时间线**（最近 10 条），不是只取当前通道：

- 当面通道里她自己的话按原样（`{"对白": ...}`）回灌，顺带强化 JSON 格式；
- 手机通道的纯文本会包回 `{"消息": ...}`，和她的输出格式保持一致。

所以切到手机不会忘了刚当面聊的，切回当面也记得手机里说了什么。系统提示词另外还有一段
**世界块**：

```
【此刻】第一天 07:16
【最近发生的事】（按时间先后，越靠下越新）
- 10 分钟前｜晨光晃过水面：……（突发）
- 6 分钟前｜送错的快递：门外突然响起敲门声……（突发）
- 刚刚｜青梅梦境话题：……
```

事件表里只有「第一天 07:10」这种绝对时间，模型容易把它读成"早上发生过的旧事"——
明明刚响的敲门声，她会回一句"哦……早上那个"。所以这里按当前故事时间换算成
**「刚刚 / N 分钟前 / N 小时前」**，并把「此刻」一起给她。

### 手机面板：可拖可缩的浮动窗口

右上角 📱 打开的手机面板是一个**浮动窗口**，而不是遮罩弹窗：

| 行为 | 说明 |
|------|------|
| 背景 | 完全不遮不糊（`background: transparent` + `backdrop-filter: none`），聊天区照常可见 |
| 拖动 | 按住标题栏拖到任意位置（手机上不启用，铺满一屏更好点） |
| 缩放 | 右下角拖拽调整大小，最小 260×220 |
| 记忆 | 位置与尺寸存在本机 `localStorage`（`yuxia_phone_win`），刷新后回到原位 |
| 交互 | 遮罩 `pointer-events: none`，窗口以外的地方照常能点、能聊 |
| 关闭 | 右上角 ×，或按 Esc |

### 场景与环境

- 环境描写绑定「地点 + 时段（清晨/白天/傍晚/夜晚）」，首次进入时生成一次并写入 `locations.variants`
- 主界面顶部显示当前地点，下面一行是该场景的环境描写，随进入的场景和时段切换
- 点击地点名可以打开地点列表，选择后玩家移动过去
- 列表顶部有「带尤夏一起去」勾选：勾上之后选地点，两个人一起过去（异地时该项不显示）
- 聊天里也可以用 `/带 厨房` 直接拉着她一起走，`/去 厨房` 仍然是自己一个人过去
- **她也能带你走**：自主行动里的 `lead` 会拉着你一起换地方（仅同处一地时可用），
  以「世界旁白」提示；这条只在 `AUTONOMY_PROMPT` 里被要求"偶尔用"
- 两人不在同一地点时：顶部显示"尤夏在 X（你在 Y）"，输入框变成发手机消息

**场景可以新建，不是固定清单**：地点表初始 11 个，之后有四条创建路径——

| 谁 | 方式 |
|---|---|
| 场景观察者 | **每轮读对话上下文**，发现「人物进入/前往了地点表之外的场所」就自动登记并更新位置 |
| 玩家 | 地点下拉底部的「去没去过的地方…」输入框，回车即创建并前往 |
| 玩家 | 聊天框输入 `/去 某个新地名` |
| 尤夏 | 自主行动判定 `move` 时，若故事需要可以走到清单外的新地点 |

新场景首次进入会自动按当前时段生成环境描写并缓存；创建受 `LOCATION_CAP`（默认 40）上限约束，
尤夏自主新建还受开关 `AUTONOMY_ALLOW_NEW_LOCATION` 控制，场景观察者由 `SCENE_WATCHER_ENABLED` 控制。

### 两人的动作描写

她自己只输出「对白 / 消息 / 表情包」，**动作由独立的一层生成**：

- 每轮对话后，`services/character_writer.py` 根据当前情境、双方位置、最近事件与最近对话，
  写一到两句**两个人**的动作描写（30-70 字）
- 写的是"尤夏做了什么 + 青梅做了什么 + 两人怎么呼应"（递、抬眼、让开一步），
  而不是只盯尤夏一个人的神态；青梅的部分只能写上下文推得出的动作，不给他编台词、不写心理活动
- 两人不在一起时不会写出"递东西、对视"这类只有同处一地才可能发生的动作
- **青梅是女生**：模型写成「他」会由 `core/pronoun.py` 确定性纠正成「她」
  （其他 / 他们 / 吉他 / 他乡 这类正常词不受影响）
- 通过 SSE `yuxia_state` 推给前端，渲染成她发言下方的一行浅灰斜体文字
- 落库到 `messages.channel = 'state'`，重进会话时仍能看到最后一条
- 由 `CHARACTER_DESC_ENABLED` 控制开关

实际输出（真实 flash）：

```
尤夏把手机往被面上一扣，猫耳仍低低压着，尾巴尖贴着床沿又蜷紧些；
青梅没松开环在腰上的手，只稍稍抬眼，腿往旁边让开半寸。
```

### 自主行动

尤夏是否行动**由她自己判断**（不再掷骰子）。两种时机：

| 触发 | 说明 |
|------|------|
| 每轮对话后 | 都会问她一次"要不要接着做点什么"，由模型决定 none / 动手做事 / 开口 / 发消息 / 换场景 |
| 闲置轮询 | 前端每 8 秒请求 `/api/idle`，同样由模型判断（会告知她玩家已经多少秒没说话） |

判断依据（写在她的提示词里）：上一句说了要做的事就做完 → **「最近发生的事」里有没有还没回应的**
（东西坏了、有人敲门、消息提示音）→ 有悬着的话题就接上 → 都没有时优先**动手做点什么**。

每次判断都会附带这些素材（实时从库里取，不是缓存）：

| 素材 | 来源 |
|------|------|
| 当前地点 / 时段 / 场景描写 | `locations` + `core.scenes` 的时段缓存 |
| 最近发生的事（含随机事件，标「突发」） | `events` 表最近 6 条 |
| 你此刻在做的事 | `conversations.yuxia_activity` |
| 你最近自己做过的事（禁止重复） | `conversations.autonomy_tail` |

### 她自己会动手（act）

除了说话和走路，她还能真的做一件事：`act` —— 写一句"她在做什么"，系统会

1. 更新「此刻在做」（之后每一轮的对话/自主行动提示词都会带上，直到过了一个时段）；
2. 记一条事件（时间线 + 故事进展面板可见）；
3. 同处一地时以「世界旁白」呈现给你，异地则不打扰你，只在故事进展里留痕。

连续 5 次自主行动的真实输出（水槽水管爆开那次）：

```
#1 [act] 蹲到水槽下，扭着身子去够角阀，手被水柱冲得直缩，还是使劲拧。
#2 [act] 咬牙狠拧两圈，角阀终于卡死，水柱断成滴答，人一屁股坐在湿地砖上喘气。
#3 [act] 扶着水槽边缘站起来，从柜子里拽出旧毛巾，扔在地上吸水。
#4 [act] 踩着吸了水的毛巾挪到门口，伸手去够阳台边的拖把，鞋底在水里吱了一声。
#5 [act] 从阳台边拽过拖把，拧开水龙头冲了冲，甩两下，往厨房水面按下去。
```

### 她会先等你（等待 → 等不及 → 行动）

她说完话之后不会马上接着演，而是先给你留出反应时间。等待时长**随她自主输出的次数递增**：

```
等待 = 8 秒 × 1.8^n      （n = 你上次开口之后，她已经自主输出了几次）
     封顶 180 秒
```

| n（她已自主输出次数） | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|---|
| 等待（秒） | 8 | 14 | 26 | 47 | 84 | 151 | 180 |

也就是说：**你刚说完话的那一小段时间里她最容易被允许动，之后每做一件事就翻一档，越等越久**，
不会一直催。两个小修正：

| 修正 | 效果 |
|---|---|
| 发的是手机消息（n=0） | × 1.5 → 12 秒（你得先看到红点、打开手机） |
| 她刚问了你一句 | × 1.3 |

| 特殊情况 | 等待 |
|---|---|
| 刚动完手、还没说话 | 8 秒（允许马上补一句，交互感靠这个） |

**例外：跟过去。** 等待期里她唯一还能做的是 `move`——因为她嘴上答应了"来了"就得真的走过去。
等待期间的这次调用只允许 `move` 或 `none`，同处一地时干脆连模型都不问。

> 没有这个口子时会出现"她说'来了来了'，人却一直待在客厅"——等待规则把所有自主行动都拦住了，
> 每条玩家消息又把等待刷新一遍，于是她永远迈不开腿。

等待用的是**墙钟时间**（`conversations.last_yuxia_at` + `last_yuxia_channel`），不是故事时间，
所以"你正在打字"和"你走开了"是有区别的。等待期间连模型都不调用，只是按时返回空。

实测（她发完三条手机消息后每 5 秒问一次）：0–85 秒全部 denied，90.8 秒才放行，
然后她才发「喂——厨房那边怎么没动静了？尤夏要过去检查咯」。

### 不会原地打转

| 机制 | 说明 |
|------|------|
| 素材实时刷新 | 事件、她的活动都是每次现查，不吃情境叙述的缓存 |
| 提示词约束 | 「你最近自己做过的事」直接写进提示词，并要求不得重复 |
| 服务端去重 | 新内容与最近 6 条自己说过/做过的话相似度超阈值就丢弃（字符二元组 Jaccard + 包含度，能抓住"多加几个字"的重复） |
| 连续次数 | 动手也算一次自主输出，同样受 `AUTONOMY_MAX_CONSECUTIVE` 限制 |
| 动手预算 | 同一 12 分钟窗内最多动手 1 次（`AUTONOMY_ACT_PER_WINDOW = 1`），动手要稀，不然像在自顾自做家务 |
| 不连动手 | 两次 `act` 之间必须有一句话，不能一环接一环地做 |
| 交还话筒 | 做完一件事、又补上一句之后，她停下来等你开口；你真的走开超过 3 分钟（`AUTONOMY_AFTER_ACT_GRACE_SECONDS`）她才重新动起来 |
| 先等你回话 | 她说完话之后不会立刻接着动：对白后等 45 秒（`AUTONOMY_SPEAK_WAIT_SECONDS`）、发完手机消息等 90 秒（`AUTONOMY_PHONE_WAIT_SECONDS`），等不及了才自己行动；等待期间连模型都不调用 |
| 行动耗时 | act/move 占 2 分钟、speak/phone 占 1 分钟故事时间，事情是"花时间做完的"，不是瞬间完成 |

### 视角不能混（她自己的动作 vs 世界事件）

她动手做的事会写进 `events` 表（`tier=self`），但不能反过来当成"世界发生的事"喂给她——
否则提示词里全是一串第三人称的「尤夏从沙发上起身…」，她会跟着用第三人称说话，
被问"你昨晚睡在沙发上？"就回一个「……尤夏。」。

| 素材 | 喂给她时的形态 |
|------|------|
| 世界事件（随机、里程碑、换场景…） | 「最近发生的事」，排除 `tier=self` |
| 她自己的动作 | 「你刚才做了」（去掉「尤夏」主语） |
| 她此刻在做什么 | 「你此刻在做」 |

对话提示词里还会要求**先直接回答对方的问题**，再决定要不要补别的。

服务端只保留两条**防刷硬限制**（不是概率）：

| 限制 | 默认 |
|------|------|
| 连续自主输出上限（玩家一直不开口时，最多接着说几句） | `AUTONOMY_MAX_CONSECUTIVE = 12` |
| 闲置行动最小间隔（秒） | `AUTONOMY_MIN_INTERVAL_SECONDS = 8` |

她可以比"只在被问到时才说话"更主动（想接话、吐槽、确认对方在不在都可以直接开口），
但主动不等于话痨：依旧是短句、平语气、没表情，一次最多四条 JSON，不连续追问。

行动类型由模型判断，服务端负责校验：同处一地才能 `speak`（异地强制改成 `phone`），
`move` 会登记地点并记一条 `scene_change` 事件；走到清单外的新地点时事件标题会标注「（新场景）」。

> 想直观观察，可以跑 `python scripts/auto_test_server.py`：临时库 + 端口 5051 + 最小间隔 5 秒。

### 暂停自动推进（右上角 ⏸）

聊天区右上角有两个常驻按钮：**暂停** 与 **手机**（不再用左下角悬浮球，避免压住消息）。

点暂停后：

| 暂停的内容 | 实现位置 |
|------|------|
| 她的自主行动（不含你主动发消息后的正常回复） | `autonomy._allowed` → 直接返回，连模型都不调用 |
| 闲置轮询 | 前端 `_startIdlePolling` 不启动定时器 |
| 随机事件 / 时间观察 / 事件总结 / 反思 / 场景观察 / 神态描写 | `atmosphere` 进 SSE 后立刻 `done` |

状态按会话存在 `conversations.paused`，刷新页面、换设备都会保持一致（`/api/scene` 会回传）。
正常对话不受影响——暂停只是让"世界别自己动"。

## 时间系统

时间真值是 `conversations.story_minutes`（显示为 `第一天 07:03`）。

| 层级 | 规则 | 是否用 LLM |
|------|------|-----------|
| 基础推进 | 每条用户消息 +3 分钟（`CLOCK_MINUTES_PER_TURN`） | 否 |
| 关键词跳跃 | 晚安→次日 07:00、午饭→12:00、放学→16:30、晚饭→18:00、深夜→22:30、明天→次日 08:00 | 否 |
| 时间观察者 | 隔 2 轮询问一次，只返回枚举（NONE/NEXT_MORNING/NOON/...） | 是（只给枚举） |
| **手动拨表盘** | 前端 24 小时表盘拖动（`POST /api/time/<conv>`），只往前走、一次最多 3 天 | 否 |

LLM 永远不输出时间字符串；服务端负责换算、禁止倒退、单次跳跃上限 3 天。

### 手动调时间（像原神那样拨表盘）

右上角三个按钮中间那个时钟，点开是一个 24 小时表盘：顶端 06:00（日出）、右 12:00、
下 18:00、左 00:00，右半亮（白天）左半暗（夜晚）。拖动指针或点「清晨/正午/黄昏/深夜」，
松手后确认即可。

- 接口 `POST /api/time/<conv>`，body `{"hour": 22, "minute": 30}`（也可以给绝对 `minutes`）
- **只能往前拨**：选的时刻比现在早，就顺延到明天；一次最多拨三天
- 拨完会做三件事：
  1. 写入一条 `time_advance` 事件（"时间被拨到了第一天 22:30"），进「最近发生的事」
  2. 新时段的环境描写在后台重新生成（比如煎饼摊从白天的油烟变成夜里昏黄的灯泡）
  3. 前端补一条「时间流转：第一天 07:19 → 第一天 22:30」的旁白
- 尤夏下一轮就能看到「此刻」和这条事件，实测会说出「尤夏也刚发现天黑，煎饼还没做完」

## 随机事件分级

程序按权重抽取强度，再交给 LLM 具体化，强度写进 `events.tier`：

| 等级 | 权重 | 影响 |
|------|------|------|
| `low` | 60% | 环境层面小变化，可以完全不理 |
| `medium` | 25% | 小意外，话题偏转 |
| `high` | 12% | 打断当前场景，必须反应 |
| `major` | 3% | 剧情级转折 |

## 记忆系统

```
score = 0.5 × 0.995^经过小时 + 0.3 × 重要度/10 + 0.2 × 相关性
```

- 每轮对话写入观察；里程碑/情绪转折等事件写成高重要度记忆
- 累计重要度 ≥ 80 触发"反思"，把零散观察归纳成高层认知
- 相关性优先用向量余弦；没有 embedding 时降级为中文二元组覆盖率 + Jaccard
- 老会话首次进入 v4 时自动回填最近 60 条消息

## 思考模式

`deepseek-flash` 默认开启思考模式，本项目跟随默认值（`DEEPSEEK_THINKING = True`，`DEEPSEEK_REASONING_EFFORT = "high"`）。

- 代价：单轮约 7 秒、视觉打标约 3 秒；思考 token 计费，并会占用 `max_tokens`（视觉打标已放大到 2048）
- 思考模式下 `temperature`/`top_p` 被忽略，本项目开启思考时不再发送这两个参数
- 关闭：把 `DEEPSEEK_THINKING` 设为 `False`

## 延迟与性能

首条消息最容易"卡"，因为除了主对话，还有两个附带任务。现在两者都不在玩家等待路径上：

| 任务 | 处理方式 | 阻塞首字？ |
|------|----------|-----------|
| 自然情境撰写（额外 LLM 调用） | 首轮/过期时先用兜底叙述，**后台线程**撰写，下一轮生效（`CONTEXT_WRITER_BACKGROUND`） | 否 |
| 场景环境描写（每地点每时段一次） | `/api/scene` 立即返回 `pending: true`，**后台线程**生成，前端 1.8 秒后重取 | 否 |
| embedding 探测 | `EMBEDDING_ENABLED=False` 时完全跳过（之前每次首轮会花 4 秒连 Ollama） | 否 |

实测（`deepseek-flash` + 思考模式）：

```
首轮：服务端准备 190 ms + 模型首 token → 用户看到回复约 1.2–2.0 s（优化前 8.4 s）
后续轮：约 1.1–1.9 s
/api/scene 冷启动：0.06 s（pending），后台约 3–5 s 后可取到描写
```

调优入口：

```python
EMBEDDING_ENABLED = False        # 装好 Ollama 模型或 sentence-transformers 后再开
CONTEXT_WRITER_BACKGROUND = True # 关掉会用同步撰写（首轮 +3 秒）
DEEPSEEK_REASONING_EFFORT = "high"  # 改 low 可再快一些
```

排查用：`python scripts/timing_probe.py`（打印请求内各阶段耗时），或用 `YUXIA_TIMING=1 python app.py` 在服务端日志里看分段。

## 安全

- 所有按 `conversation_id` 的接口都做归属校验（用户 2 读不到用户 1 的场景/手机/事件）
- `config.py` 在 `.gitignore` 中，不会误提交
- 用户 Key 只存浏览器 localStorage，仅请求头透传
- `/api/config` 只暴露"服务端是否配置了 Key"的布尔值

## 已知限制

- 官方 API 没有 embeddings 接口，语义检索依赖本地 Ollama / sentence-transformers，都没有时用中文词面相似度
- 时间观察者会依据语义跳跃（例如提到吃饭可能直接跳到饭点），觉得太激进可以调大 `TIME_OBSERVER_INTERVAL`
- 思考模式偶尔会让模型漏掉严格 JSON 格式，服务端会把纯文本按当前通道兜底存成一条消息
- 老库里的 `conversation_summaries` / `prompt_config` 是历史遗留表（数据保留，代码不再写入）
